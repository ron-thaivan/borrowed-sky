This document records the earlier browser-compatible port into Node. The later Python prototype repairs are documented in [`backend/README.md`](../backend/README.md); they keep the installed TCP workers separate from the website and do not replace the Node coordinator. The source comparison and verification below describe the original integration, not the current Python prototype implementation.

Compared `origin/thapas2-branch` with main at `3c16159`. The Python branch was read with `git show`; it was not merged, modified or deleted.

## Ported behavior

- `public/device-info.js` creates a cryptographically random UUID, stores it in local storage and reuses it across visits/tabs for that origin. Blocked storage falls back to page-lifetime identity; absent randomness yields no label. It uses `getRandomValues`, so it does not depend on secure-context-only UUID helpers on LAN HTTP.
- Reports contain only an optional UUID, logical processor count, approximate memory and allowlisted OS/browser labels. No high-entropy Client Hints are requested. Raw user-agent strings and versions stay out of reports.
- `server.mjs` validates initial registration reports and authenticated state updates before storing them. Legacy clients may omit reports. A supplied report replaces the old one, including null unavailable measurements; omission preserves the previous report. Receipt timestamps come from the coordinator.
- `lib/dashboard.mjs` returns a fresh, flat public snapshot with a shortened browser label, environment, resources and receipt time. Full persistent UUIDs and session secrets are not exposed in fleet snapshots.
- `public/dashboard.js` retains rankings, accepted-work statistics and authoritative statuses. Additional columns explain client-reported environment and hardware; unavailable data is explicit. The existing ID column is labeled Session ID to distinguish it from the persistent browser label.
- Names remain user-selectable. An unnamed new contributor can receive a recognizable browser-based name; old clients keep the existing generated name fallback.
- IDs/reports never select jobs, authenticate a request, merge sessions, deduplicate workers or change benchmark counting. Copying a browser label gives no authority. The browser label identifies storage, not a verified physical machine.

## Intentionally not ported

No second coordinator, TCP listener, installed rendering worker, psutil, CPU-utilization monitor, exact/free RAM probe, physical-core count, hostname, OS release, processor architecture or GPU fingerprint. These are unnecessary, unavailable through ordinary browser APIs, or more identifying than this demo needs. No replacement of room authentication, assignment, rendering, collection or recovery was made.

The [HTML hardwareConcurrency definition](https://html.spec.whatwg.org/multipage/workers.html#dom-navigator-hardwareconcurrency) describes logical processors potentially available to the browser, which may be fewer than the actual machine has. The [Device Memory specification](https://www.w3.org/TR/device-memory/) describes a coarse RAM estimate with browser-defined bounds and secure-context restrictions. It is not available/free RAM. Ordinary LAN HTTP and some browsers will legitimately report no memory information. OS/browser labels can be masked and are informational only.

Validation bounds are 1–1024 integer logical processors and 0.25–1024 GiB power-of-two memory estimates. Unknown environment values and additional fields are rejected. These limits bound input, not supported rendering workload or verified hardware capabilities.

## Verification

- Complete suite: `node --test` — **85 passed, 0 failed** on Node 24.22.1.
- Six new tests cover browser identity reuse across reloads/tabs, separate profiles, absent APIs, blocked storage, malformed IDs, missing memory, strict resource validation, registration, legacy clients, multiple independent sessions, authorization, reconnect updates, stale upload rejection and lease renewal with reports.
- Existing rendering fixtures, GIF validation, failure simulation, heartbeat recovery, pause/resume, benchmarks and browser-controller tests remain intact.
- Browser integration checked actual reported values, identity preservation on refresh and separate sessions sharing a browser label. A real 60-frame render completed with 31 host frames and 29 contributor frames, producing a 1.60 MiB GIF. Neither browser tab reported console warnings or errors. Functional checks use one physical machine, not physical multi-laptop testing.
- The local port-3000 coordinator was restarted while idle with the integrated code, and a fresh host room was left ready. The isolated test coordinator was stopped.
